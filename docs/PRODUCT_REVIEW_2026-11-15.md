# Tally 产品评审（2026-11-15）

> 视角：以「一个每天用它下单、每周用它复盘的手动交易者」为唯一用户。
> 方法：逐页读实现 + 交叉验证入口与数据来源；行号对应当前工作区。
> 结论先行：**执行层已经是好产品，复盘层正在变成功能仓库。**

---

## 0. 一句话结论

Tally 的真正护城河是**交易上下文**：成交、持仓、风控、MFE/MAE、滑点、开仓当时的清单，全部是系统副产物，不需要用户导入或补录。这一点目前没有第二个页面能替代。

问题出在复盘层：一天之内上线了 5 个复盘页面（例行、错过、趋势、分析、评分，提交 `6a0bb51`），加上更早的日历与策略页，每个需求都变成了一个一级导航项，但没有一次「收敛」——于是出现了三套纪律系统、四个统计页面、十几个重复入口，以及若干只有展示没有动作的半成品区块。

判断标准只有一条：**这个功能能不能改变下一笔交易或下一次复盘的行为？** 不能的，就是装饰。

## 1. 现状：功能比使用节奏多

从使用频率看，15 个页面实际上分三档：

| 频率 | 页面 | 现状 |
|---|---|---|
| 每天 5–20 次 | 交易台、概览 | 好用，但有几个断点（见 3.1） |
| 每天 1 次 | 交易日志、盈亏日历 | 好用，和报表大量重复 |
| 每周 1 次 | 历史复盘、策略手册 | 核心差异化，缺闭环 |
| 每月 0–1 次 | 统计报表、绩效趋势、深度分析、过程评分、执行质量 | 四个页面回答同一个问题 |
| 几乎不打开 | 例行清单、错过机会、审计日志 | 与主流程没有连接 |
| 一次性 | 设置（12 分区 / 100+ 项） | 过载，且与顶栏、命令面板重复 |

单人产品的导航不该有 15 项。用户不需要「功能齐全」，需要「今天做完该做的事」。

## 2. 功能地图与判断

图例：**核心**＝保留并强化；**保留**＝有价值但降级；**合并**＝并入其它页面；**降级**＝移出主导航；**删除/占位**＝没有独立存在理由。

| 模块 | 解决什么问题 | 完成度 | 判断 |
|---|---|---|---|
| 概览 | 今天账户怎么样 | 中（4 指标 + 最近交易 + 评分卡） | **核心**，但缺「今天该做什么」 |
| 交易台 | 看盘、下单、管仓 | 高 | **核心**，修断点 |
| 历史复盘（回放） | 重演行情、刻意练习 | 高 | **核心**，补数据持久化 |
| 交易日志 | 每笔交易的事实与标签 | 高 | **核心**，与报表去重 |
| 盈亏日历 | 每天怎么样 + 日笔记 | 高 | **核心**，强化「当日复盘」入口 |
| 策略手册 | 把做法写成规则并验证遵守度 | 高 | **核心**，接入例行与门禁 |
| 例行清单 | 盘前/盘中/盘后打勾 | 中 | **合并**（进策略页或今日工作台） |
| 错过机会 | 看对没做的机会 | 中 | **保留**，但必须能进回放 |
| 绩效趋势 | 近期是否退化 | 中 | **合并**（并入分析页） |
| 深度分析 | 多维度归因 | 高 | **合并**（作为分析页主视图） |
| 过程评分 | 一个综合分 | 中 | **降级**（只留概览卡） |
| 统计报表 | 区间汇总全貌 | 高 | **核心**（吸收执行质量） |
| 执行质量 | 滑点/延迟/拒单 | 中（只读） | **合并**（报表页签） |
| 审计日志 | 操作留痕与对账 | 中 | **降级**（设置→诊断） |
| 设置 | 所有配置 | 高但过载 | **保留**，做减法 |
| 命令面板 | 快速跳转/动作 | 中 | **保留**，补缺口 |
| AI 复盘 | 日/周总结 | 中（默认关闭） | **保留**，入口要可见 |
| Pine / 指标模板 / 画线模板 | 图表自定义 | 实验级 | **降级**（收进图表工具栏） |

## 3. 逐项评审

### 3.1 交易台与执行层（核心，最该修）

**做得好的**：下单票的风险反推、模板分批止盈、提交前券商预演、图上拖线改 SL/TP、挂单停手节流、两击确认的平仓/急停、纪律门禁直接嵌在确认弹窗里——这些是把「执行纪律」做成产品，而不是做成提示。

**断点（按影响排序）**：

1. **「点击图表设置委托价」实际不可达**。`handleChartClick` 挂在父容器上并要求 `event.target instanceof HTMLCanvasElement`（ChartPanel 963–977、1086），但图表在 same-origin iframe 里，父容器收不到图内点击（同文件 729–731 注释已写明）。用户点击图表不会改价，只会困惑。→ 要么用库的 `crosshair_moved` + `mouse_down` 落实，要么删掉提示文案。
2. **持仓没有 SL/TP 时，图上无法新建**：只有已有 SL/TP 才画可拖线（ChartPanel 568–655）。「补一个止损」是最高频的风险动作，却只能在 MT5 里做。→ 持仓面板或图上补「设置止损/止盈」。
3. **挂单只能改价**：不能改手数、SL/TP（ChartPanel 1024–1035）。→ 至少允许改量。
4. **撤单交互不一致**：图上 × 单击直接撤（562–565），列表里两步确认。→ 统一为可撤销 toast 或统一二次确认。
5. **划线中无法在票内取消**：「划线中」按钮再点仍是 `activate()`（OrderTicket 572–584），只能 Esc / 图上清除 / 入场块 ×。→ 按钮做 toggle。
6. **block 模式未配清单时只给一句话**（OrderTicket 1198–1200），弹窗内没有「去设置」跳转；`TradeReviewDrawer` 没有策略时同样只有文字（226–230）。→ 空态一律给按钮。
7. **告警不能编辑价格/备注/重复规则**（AlertsPanel 97–104 只发 enabled），删除无确认；告警与财经日历两个右侧面板同时打开会互相覆盖（App.tsx 304–305）。
8. **多图布局下价格取整用全局品种参数**（ChartPanel 330 vs 362–365），副图品种与主图不同步时会按错误 tick 取整。
9. **平仓/全平/急停无 busy 与成功反馈**（TopBar 96–130、PositionsPanel 115–127），高频操作缺少「已执行」确认。
10. 订单票提示「Shift 吸附整数位」（1038–1049），但该逻辑只作用于图上拖线，票内数字输入无效。

### 3.2 交易日志 / 统计报表（同源，应合并视角）

两页都用 `journal.stats`：日志顶部 6 张卡 + 分组表现，报表 8 个指标 + 4 张分组 + 模板执行 + 执行成本 + 曲线。净盈亏、胜率、盈亏比、期望、最大回撤、按品种/时段/标签**完全同源**。

- 用户的问题只有一个：「这段时间打得怎么样」。现在要在两页之间切换才能拼出答案。
- 日志只有 7/30/90 天，没有品种/标签/结果筛选；报表有 7/30/90 但没有「全部」。
- 行内三键「交易图 / 复盘 / 回放」与整行点击打开详情重复（Journal 307–310、386–407）；详情弹窗里又有一个「在回放中重演」（TradeDetailModal 101–110）。
- 详情弹窗的「截图页签」初始入口不可达：两处调用永远传 `chart`（Journal 309、390；442）。
- 统计卡、分组条、图表都不可点击，无法从「EURUSD 亏得多」下钻到那几笔交易。

**建议**：日志 = 事实与操作（筛选、标签、复盘、回放）；报表 = 汇总与归因。报表吸收「执行质量」与「深度分析」，日志顶部只留 3 个关键指标 + 一句结论。

### 3.3 复盘层：7 页、三套纪律、没有主线

这是当前最需要做减法的区域。

**三套纪律系统互不相通**：

| 系统 | 载体 | 触发时机 | 数据 |
|---|---|---|---|
| 开仓纪律门禁 | 策略手册的 playbook 规则 | 下单确认弹窗 | `pre_trade_gates` |
| 例行清单 | 盘前/盘中/盘后任务 | 每天手动打勾 | `routines` |
| 策略遵守度 | 同一批 playbook 规则，事后勾选 | 复盘抽屉 | `playbook_checks` |

用户在「例行清单」里维护一套每天的检查项，又在「策略手册」里维护一套开仓规则，再在「设置→开仓纪律」里选默认清单——三处都要维护，彼此不知道对方存在。**这是典型的「为了做而做」：两块功能都实现了，但没有合成一个「纪律」概念。**

**各页问题**：

- **盈亏日历**：完成度最高（月历、日笔记、模板、导出 PNG/PDF、AI 总结）。问题是 AI 面板一开，笔记卡位置会跳（Diary 388 起的两栏 grid）；日历只能按月翻，无年视图/日期跳转；明细行「复盘」不写策略时不给建策略的按钮。
- **策略手册**：遵守度、破例率统计做得扎实。但统计卡片不可下钻到关联交易；归档后没有「已归档」分区，无法恢复；规则勾选只能在复盘抽屉里做，策略页没有入口。
- **例行清单**：与门禁无关，只能逐日 ±1 天，热力图固定 13 周且不可点，归档项不能恢复。
- **错过机会**：思路对（理论值不进绩效），但**不能进回放**——这恰好是它最有价值的下一步（「如果当时做了会怎样」），目前只能看模拟的 MFE/MAE；列表无区间/品种筛选，`missed.list` 甚至不带 days。
- **绩效趋势 / 深度分析**：两页同源 `review.trades`，一个画滚动曲线 + 散点，一个做筛选 + 分组 + 交叉矩阵。指标（胜率/期望/平均 R/净盈亏）与报表重复；散点选中后看不到标签、笔记，也不能打开详情或回放之外的动作；交叉矩阵格不可点。
- **过程评分**：公式透明、带版本、样本不足会剔除分量——工程质量很高。但它自己的对标文档就写着「综合分只能做导航，不能做目标」，而且 7 个分量里 6 个与报表重复。**它更适合作为概览页的一张卡，而不是一个独立页面。**

**缺失的主线**：没有任何页面回答「今天复盘完了吗」：日记页不知道策略规则有没有勾、例行清单有没有打勾、错过的机会有没有回放。复盘被拆成 7 个抽屉，用户得自己记着去拉。

### 3.4 回放（差异化最强，但有数据风险）

**做得好的**：参照层（价格线 + 开仓前缓冲 + 逐笔成交灰标）、重演预填、实盘 vs 重演对照、来源筛选、从日志/日记/散点三处进入——这条链路已经在同类产品里领先。

**问题**：

1. **所有回放会话、图表状态、画线都存在 localStorage**（`src/replay/store.ts` 129/153，`ReplayChart` 82–138）。清缓存、换机器、重装即永久丢失；也没有导出/备份入口。训练记录是用户资产，应该进网关数据库并纳入现有备份体系。
2. 会话上限 60（`ReferenceCapacityDialog`），到顶只能删旧的；没有「归档后再训练」的批量管理。
3. 报告页与参照面板同源重复展示实盘字段（ReplayReport 210–308 vs ReferencePanel 119–194）。
4. 报告交易明细不可点击，无单笔下钻；对照只认第一笔 `referenceRole === 'retry'`。
5. 回放图不复用交易台的指标模板/画线模板（ChartPanel 1100–1101 仅交易台），用户要重新搭一遍图。
6. `ReplayCreate` 的「数据覆盖」色条是按固定数字画的装饰（298–308），预热根数写死 1000（282–287），自定义区间不会重算点差/货币（75–85）。
7. 回放列表的「继续/报告」同时出现在卡片与表格行，删除确认在工作台与列表两处不一致（工作台无确认）。

### 3.5 设置、命令面板与全局

- 设置 12 个分区、约 100+ 可改项，其中「画线工具」「双介质界面」「第三方通道」只有说明文字无操作，「自动检查 已启用」是静态文本（SettingsPanel 898–953、1702–1711、1903–1905）。
- 布局与联动、模板编辑、账户切换、导出/备份/更新、主题，在设置页、顶栏、命令面板各有一套入口。
- 命令面板 30 个动作，但缺少「开仓纪律」「AI 复盘」两个设置分区（CommandPalette 27–38 vs SettingsPanel 65–78），导出日志固定 30 天（89–101）。
- 隐私模式只覆盖 8 个使用 `usePrivacyMask` 的页面；回放报告、AI 面板、导出卡片不遮（Diary 有拦截，Replay 没有）。
- **时区只接了一半**：`_server_offset` 由 tick 时间推算（worker_account 470–476），但只在有报价推送时更新；Diary / Analysis / 复盘抽屉会减 offset 做日期分组，而 Journal 列表（`views/Journal.tsx:33`）、`journal.stats` 的时段分桶（`journal.py:469`）与统计窗口起点（`journal.py:399`）、报表曲线的日期标签都没减。券商服务器时区（常见 GMT+2/+3）与本机不同时，同一笔交易在日志/报表与日历里会按两套时间口径呈现。这是目前最隐蔽的正确性问题。

### 3.6 明显「为了做而做」的清单

| 功能 | 为什么像「为了做」 | 建议 |
|---|---|---|
| 过程评分独立页 | 自己的对标文档定为 P2，指标与报表重复，无行动出口 | 概览卡 + 点开看分量弹层 |
| 审计日志一级导航 | 开发者/对账工具，用户每月看一次 | 移入设置→诊断，保留「立即对账」 |
| 执行质量独立页 | 数据独特但只读、无下钻、与报表「执行成本」重复 | 报表内页签 + 拒单原因链接到日志 |
| 绩效趋势 + 深度分析 + 统计报表 | 三页回答「我打得怎么样」 | 合并为一页三视图（趋势/分组/交叉） |
| 三套纪律系统 | 例行、策略规则、开仓门禁各自维护 | 统一为「纪律」：规则 + 每日任务 + 门禁 |
| 49 种图表布局 | 选择成本高于收益 | 6 个常用 + 自定义 |
| Pine 脚本（实验） | 单人 MT5 用户的实际使用率极低 | 留在设置且标实验，不做主路径 |
| 双介质界面 / 第三方通道 / 画线工具说明卡 | 占位文案 | 删除或做成真实功能 |
| 复盘容量 60 的对话框 | 用弹窗处理容量问题，本质是存储方案没做完 | 会话入库 + 归档 |

## 4. 真正的缺口（按 ROI 排序）

1. **「今天」工作台**：盘前清单 → 开仓门禁状态 → 今日交易 → 待复盘笔数 → 一键继续复盘/回放。把 7 个复盘页收束成一条日常路径。
2. **补齐时区消费端**：`_server_offset` 已有（tick 驱动），但启动/无报价时可能为 0，且 Journal / `journal.stats` / 报表曲线没有减 offset。统一格式化与分桶函数，让日历、分析、日志、报表一致。
3. **复盘闭环**：交易 → 复盘（评分/规则）→ 回放 → 重演 → 对照 → 标记完成；每步都有返回上一步的链接。现在每一跳都是单向的。
4. **回放数据持久化与备份**：会话/画线/笔记从 localStorage 迁到网关库，进入 `data.backup`；提供导出。
5. **交易台补口**：持仓可设 SL/TP、挂单可改量、图表点价修复、告警可编辑、急停/平仓有 busy 与结果提示。
6. **统计口径单一来源**：已有 `stats_golden.json` 跨端黄金样本，把报表/日志/分析/评分全部收敛到同一 summary，页面只做呈现。

## 6. 优先级建议

**P0（先修正确性与断点，1–2 周）**
- 时区接线（影响所有日期统计）
- 图表点价不可达、持仓无法新建 SL/TP、挂单不能改量
- 回放会话持久化 + 备份
- 日志/报表同源指标合并展示，去掉重复入口
- 复盘闭环补「返回」与「标记已复盘」

**P1（结构收敛，2–4 周）**
- 15 页 → 8 页；过程评分/执行质量/审计降级
- 今日工作台
- 三套纪律合并
- 命令面板补齐、设置占位清理、告警编辑

**P2（打磨）**
- 图表模板系统收敛；49 布局收缩
- 复盘报告下钻与导出扩展
- AI 复盘入口可见化

## 7. 一句话给每个模块的判词

- 交易台：**这是产品**，别再加功能，先补洞。
- 日志：**事实层**，别让它变成第二个报表。
- 日历：**每天的入口**，把它做成「今天」而不是「月历」。
- 策略：**纪律的家**，把例行和门禁搬进来。
- 回放：**护城河**，先把数据存好。
- 报表/趋势/分析/评分：**一个问题的四种问法**，留一种。
- 例行/错过：**两个好点子**，但都没连上主线。
- 执行质量/审计：**专业工具**，收进抽屉更合适。
- 设置：**能删一半**。
