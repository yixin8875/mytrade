# Tally 复盘 · 行情回放产品文档（PRD v1.0）

> 日期：2026-11-14  
> 状态：待评审，未开发  
> 关联文档：[UI_AND_REPLAY_PLAN.md](UI_AND_REPLAY_PLAN.md)（信息架构与视觉方向）、[DESIGN.md](../DESIGN.md)（终端整体设计）  
> 本文取代 `UI_AND_REPLAY_PLAN.md` 第 4 节，作为回放/复盘功能的开发依据。

---

## 0. 一页结论

做一个和实盘交易台**物理隔离**的「复盘」工作台：

1. 选择品种、日期区间和初始资金，创建一次复盘会话。
2. 用 M1 K 线作为唯一数据底座，按「已处理到的最后一根 M1」推进虚拟时钟，图表只能看到游标之前的数据。
3. 在当前游标上模拟下单、改单、平仓、拖 SL/TP，撮合在本地完成，**绝不调用 MT5 的 `order_send`**。
4. 随时记笔记、截图、打标签；右侧实时显示模拟账户、持仓、统计。
5. 结束后生成复盘报告：资金曲线、回撤、胜率、盈亏比、R 倍数、MFE/MAE、分时段/标签统计、规则执行情况，并与实盘交易日志同口径对比。

**MVP 建议范围**：单品种 + M1 回放 + 模拟市价/挂单/持仓 + 基础统计/笔记 + 崩溃恢复。  
**MVP 预计**：约 3 周开发（详见第 24 节）。

三个必须守住的产品底线：

- **不能泄漏未来数据**：图表、日历、报价、搜索、指标都不能看到游标之后的信息。
- **不能误触实盘**：复盘页面没有实盘模式，不调用任何真实下单接口，始终显示「模拟」标识。
- **不能污染实盘统计**：复盘成交单独存库，不进入交易日志、执行质量、审计和实盘统计。

### 1.4 本版新增的产品决策

1. **单品种会话**：MVP 一个会话只交易一个品种；多品种参考图后置。
2. **M1 为唯一底座**：所有显示周期由 M1 聚合，保证跨周期一致、可复现。
3. **前端回放与撮合引擎**：网关只负责数据、持久化和统计；回放推进不依赖 WebSocket 往返。
4. **固定点差 + 可配佣金**：MVP 不做浮动点差、隔夜利息和 tick 级滑点。
5. **OHLC 保守撮合**：同一根 K 线内 SL/TP 同时触发时按 SL 先成交；跳空按开盘价成交。
6. **不支持后退单步**：MVP 只前进、重开；「回看历史」不改会话状态；「回到此处重做」后置。
7. **离线可复盘**：数据准备好后，MT5 断开也能继续回放。
8. **不做自动策略回测**：复盘是手动决策训练，不是参数优化器。

## 2. 产品定位

### 2.1 要解决的问题

- 实盘交易日志只能看到「已经发生的交易」，无法重现当时的行情、逐根 K 线做决策。
- 想验证一个形态或策略，需要反复找历史片段，现有工具只能看静态图表。
- 想训练纪律（止损、仓位、不过度交易），但实盘试错成本高。
- 复盘时缺少「当时为什么进场、错在哪里」的结构化记录，事后只能凭记忆。

### 2.2 产品目标

- **可重复**：同一个会话、同一串操作，结果完全一致。
- **可信**：成交、止损、盈亏、统计口径贴近真实交易，且明确标注近似之处。
- **专注**：图表为主、控件克制，不让回放变成另一个实盘终端。
- **可回顾**：每次会话留下交易、笔记、截图和一份可读的报告。

### 2.3 成功标准

| 指标 | 目标 |
|---|---|
| 创建会话耗时 | 数据已缓存时 < 10 秒；首次准备 1 个月 M1 < 30 秒 |
| 回放流畅度 | 10x 速度下图表更新稳定，无明显卡顿 |
| 未来数据泄漏 | 0 起（自动化检查 + 人工验收） |
| 实盘误触 | 0 起（代码层隔离 + 验收项） |
| 崩溃恢复 | 最多丢失 5 秒游标，不丢已提交订单/成交/笔记 |
| 统计一致性 | 同一批成交，报告与手工计算误差 < 0.01 |
| 完成一次典型复盘 | 用户从创建到看到报告 < 15 分钟（不含行情本身时长） |

### 2.4 非目标（明确不做）

- 不做自动策略回测、参数优化、walk-forward。
- 不做多用户、云同步、社区分享。
- 不做真实下单，不读取实盘账户余额作为复盘资金（可一键填入，但会快照）。
- 不做 tick 级回放（R4 再评估）。
- 不做 Prop 公司挑战/通过率模拟（R4 再评估）。
- 不复制第三方复盘产品的品牌、文案和专有视觉。

## 3. 用户与核心场景

**用户**：单个手动交易者，日常在 Tally 交易台看盘/下单，希望盘后或周末做刻意练习。

### 场景 A：盘后复盘当天行情

- 选中当天品种和日期，从亚盘开始回放。
- 在关键位置模拟自己当时会做的单，记录「为什么进、为什么没进」。
- 结束后看报告：如果按计划做，盈亏会是多少。

### 场景 B：验证一个形态/策略

- 选过去 3 个月，随机起点，避免记住走势。
- 只做符合形态的机会，强制自己等待。
- 多场会话后对比胜率、期望、R 分布。

### 场景 C：纪律训练

- 设置单笔风险 0.5%、日亏 2%、每日最多 3 笔。
- 违反规则时记录违规；严格模式下直接拦截。
- 报告里看违规次数和违规后的盈亏。

### 场景 D：离线回顾历史

- 已缓存过数据，MT5 未启动也能打开会话继续复盘。
- 适合出差、周末、终端维护时使用。

## 4. 术语与统一口径

| 术语 | 定义 |
|---|---|
| 复盘 / 回放 | 本模块。行情按历史逐根推进，用户手动决策。 |
| 会话 | 一次复盘任务，包含品种、区间、初始资金、成交、笔记、状态。 |
| 游标 `cursor_ts` | 已处理到的最后一根 **M1 的收盘时间**（服务器时间）。游标之后的数据不允许渲染。 |
| 基准周期 | 固定 M1。所有推进、撮合、聚合都以 M1 为单位。 |
| 显示周期 | 图表当前周期（1m/5m/15m/30m/1h/4h/1D/1W/1M），由 M1 聚合。 |
| 预热区 | 会话开始前额外加载的 M1，用于指标计算和看图，不可交易。默认 1000 根。 |
| 模拟账户 | 会话独立的余额/净值/保证金，不与 MT5 账户联动。 |
| 服务器时间 | 沿用交易台约定：MT5 K 线时间按「服务器时间当作 UTC」处理。界面统一标注「服务器时间」。 |
| 会话区间 | `[start_ts, end_ts]`，按服务器时间；`end_ts` 含最后一根 M1。 |
| 有效回放时长 | 区间内实际有行情的 M1 数量，不含周末/休市。进度按 K 线数量计算，不按墙钟。 |

## 6. 核心用户流程

### 6.1 创建并开始

```
复盘列表 → 新建复盘
  → 选品种
  → 选区间（预设/自定义/随机）
  → 数据覆盖检查（进度/缺口）
  → 设置初始资金、点差、佣金、杠杆
  → 设置默认显示周期、预热根数
  → 创建并准备数据
  → 数据就绪 → 进入工作台（默认暂停在第一根可交易 K 线）
```

### 6.2 回放与交易

```
进入工作台（暂停）
  → 播放 / 单步 / 跳到下一根显示周期
  → 图表推进，右侧账户实时变化
  → 下单（市价在下一根 M1 开盘成交；挂单在后续 K 线触发）
  → 成交后显示持仓线、SL/TP 线、成交标记
  → 可改 SL/TP、平仓、部分平仓、全部平仓
  → 随时记笔记 / 截图 / 打标签
  → 暂停时自动保存游标与状态
```

### 6.3 结束与报告

```
点击「结束复盘」
  → 若还有持仓：提示「按当前价平仓并结束」
  → 状态改为 finished
  → 生成报告（统计在网关计算）
  → 进入报告页
  → 可「重新挑战」（复制参数，清空成交和笔记）或「归档」
```

### 6.4 中断与恢复

```
应用退出 / 崩溃 / 断网
  → 会话保留最近一次保存的游标、余额、订单、持仓、笔记
  → 再次进入会话
  → 提示「继续上次回放？」（默认继续）
  → 从保存点恢复；若保存点之后有未落盘动作，按动作日志重算
```

## 7. 复盘列表页

### 7.1 顶部统计卡

四张卡，数据来自全部未归档会话：

| 卡片 | 口径 |
|---|---|
| 进行中 | 状态为 `running` / `paused` 的会话数 |
| 累计模拟盈亏 | 所有已结束会话的净利润之和（会话货币不一致时只统计当前账户货币，并提示） |
| 总交易笔数 | 所有已结束会话的已平仓交易数 |
| 已完成复盘 | 状态为 `finished` 的会话数 |

### 7.2 进行中会话卡

- 只显示最近 1 个未结束会话（按 `updated_at`）。
- 内容：会话名、品种、显示周期、区间、当前游标、进度条、模拟盈亏、浮盈、持仓数、最后更新时间。
- 主按钮：「继续复盘」。
- 次按钮：`···` → 重命名、复制参数、归档、删除。

### 7.3 筛选与会话表格

筛选：

- 状态：全部 / 进行中 / 已结束 / 已归档。
- 品种：下拉，选项来自已有会话。
- 搜索：会话名模糊匹配。
- 排序：最近更新 / 创建时间 / 盈亏 / 交易数。

表格列：

| 列 | 说明 |
|---|---|
| 名称 | 可点击进入；默认 `XAUUSD · 10-01 ~ 10-31` |
| 品种/周期 | `XAUUSD · 15m` |
| 区间 | 服务器时间日期 |
| 进度 | `68%` 或 `已完成`；进行中显示游标 |
| 状态 | 进行中 / 已结束 / 已归档 |
| 模拟盈亏 | 已结束会话净利润；进行中显示当前净值变化 |
| 交易 | 已平仓笔数 |
| 最大回撤 | 已结束会话的最大回撤 % |
| 更新时间 | 相对时间 |
| 操作 | 继续 / 报告 / 重新挑战 / 归档 / 删除 |

空状态：

- 无会话：插画 + 「创建第一次复盘」按钮 + 一句说明「用历史行情练习决策，不会发送任何真实订单」。
- 筛选无结果：显示「没有符合条件的会话」+ 清除筛选。

## 8. 新建会话

### 8.1 表单结构

分四组，默认展开第一组，其余可折叠。

#### A. 品种与区间

| 字段 | 类型 | 默认 | 规则 |
|---|---|---|---|
| 品种 | 搜索下拉 | 当前交易台品种 | 只列 `visible` 品种；无数据时禁用并提示 |
| 区间预设 | 分段按钮 | 最近 1 个月 | 1 周 / 1 个月 / 3 个月 / 自定义 |
| 开始时间 | 日期时间 | 预设计算 | 服务器时间，精确到分钟 |
| 结束时间 | 日期时间 | 预设计算 | 必须晚于开始；至少 200 根 M1 |
| 随机起点 | 开关 | 关 | 开启后忽略用户选的开始时间，在「可用数据范围 − 区间长度」内随机；避开无数据日 |
| 默认显示周期 | 下拉 | 15m | 1m/5m/15m/30m/1h/4h/1D |
| 预热根数 | 数字 | 1000 | 100–5000；只用于指标和向左看图，不可交易 |

区间限制：

- 最短 200 根 M1。
- 最长 2 年；超过 1 年时提示预计占用空间。
- 起止时间对齐到分钟；结束时间含该分钟。

#### B. 初始账户

| 字段 | 默认 | 说明 |
|---|---|---|
| 初始资金 | 10000 | 正数，最多两位小数 |
| 账户货币 | 当前账户货币 | 只读；没有账户时用 USD |
| 杠杆 | 当前账户杠杆 | 可选 1:20 / 1:50 / 1:100 / 1:200 / 1:500 / 自定义 |
| 使用当前余额 | 按钮 | 把当前实盘账户余额填入初始资金（仅快照，不联动） |

#### C. 成本与撮合

| 字段 | 默认 | 说明 |
|---|---|---|
| 点差模式 | 固定点差 | MVP 只有「固定点差」；后续加「按品种当前点差」 |
| 点差值 | 品种当前 `spreadPoints` | 单位：point；0 表示无点差 |
| 每手单边佣金 | 0 | 账户货币；开仓和平仓各收一次 |
| 滑点 | 0 | 市价/停损单的固定不利点数；MVP 默认 0，高级设置可改 |
| 撮合严格度 | 标准 | 标准 / 严格（禁止无止损、执行券商最小止损距离） |

#### D. 训练规则（可选）

MVP 只做「提示不拦截」，R3 增加严格模式：

| 规则 | 默认 | 行为 |
|---|---|---|
| 单笔风险上限 | 关，1% | 超过时记录违规并提示 |
| 日亏损上限 | 关，2% | 当日权益回撤超过时提示/拦截 |
| 每日最多开仓 | 关，3 笔 | 超过时提示/拦截 |
| 单笔最大手数 | 关，1.0 | 超过时提示/拦截 |
| 最大同时持仓 | 关，3 | 超过时提示/拦截 |
| 必须带止损 | 关 | 严格模式下禁止无 SL 开仓 |

### 8.2 数据覆盖检查

选择品种和区间后，自动请求 `replay.coverage`，显示：

- 一条按月的覆盖条：绿色 = 数据完整，黄色 = 有缺口，灰色 = 无数据。
- 文字：`可用 2024-01-02 ~ 2026-11-08 · 预计 37.2 万根 M1 · 约 28 MB`。
- 缺口说明：`周末/节假日无行情属正常；工作日内缺失超过 5% 的交易日会标记为黄色`。
- 如果区间起点没有数据：提示「起点附近无行情，将顺延到 2024-01-02 09:00」并提供「使用该起点」。
- 如果区间内完全无数据：禁用「创建」。

### 8.3 创建后的行为

1. 创建 `replay_sessions` 记录，状态 `preparing`。
2. 若数据未缓存，启动 `replay.prepare.start` 后台任务。
3. 对话框变为进度页：`正在准备 2024-03（3/12）· 已写入 8.2 万根`，可取消。
4. 准备完成后状态 `ready`，自动进入工作台，游标停在第一根可交易 M1 的收盘时间。
5. 失败时保留会话，状态 `error`，列表里可重试。

## 9. 数据准备与缓存

### 9.1 数据源

- 复用网关现有 `history.get` 背后的 `mt5.copy_rates_range`（`gateway/mt5_worker.py`）。
- 只取 M1；显示周期由前端聚合。
- 时间语义沿用现有约定：把券商服务器时间当作 UTC，用 `datetime.fromtimestamp` 构造区间。
- 数据只存本机，不上传。

### 9.2 缓存策略

- 以「品种 + M1 + 时间」为键共享缓存，多个会话复用同一段数据。
- 按月分块写入：每块一个月，逐块提交事务。
- 去重：同一时间戳只保留一条；按时间升序。
- 数据质量：
  - 丢弃 OHLC 非有限值、high < low、价格 <= 0 的记录。
  - 工作日缺口 > 5% 标记为「部分可用」，创建会话时提示，不阻塞。
  - 周末/节假日缺口不视为异常。
- 磁盘估算：1 年黄金 M1 约 37 万根，SQLite 约 25–35 MB。列表和设置页显示当前缓存大小。

### 9.3 后台任务与交易优先级

数据准备必须**不能阻塞实盘交易**：

- `replay.prepare.start` 创建任务，网关按「一个月一块」分块执行。
- 每块之间让出命令队列；有交易指令时优先处理交易。
- 如果检测到交易指令等待超过 300ms，暂停准备，交易处理完再继续。
- 进度通过 `replayJob` 事件推送：`{jobId, symbol, from, to, doneBars, totalBars, chunk, status}`。
- 支持 `replay.prepare.cancel`；已写入的数据保留，任务标记取消。

### 9.4 数据缺失与离线

- 数据准备好后，会话可离线回放；不依赖 MT5 连接。
- 会话创建时把品种规格快照写入 `symbol_snapshot`（digits、point、tickSize、tickValue、contractSize、min/max/step、stopsLevel、currency）。
- 若用户清除缓存，已有会话的成交和笔记保留；再次打开时提示重新下载缺失区间。

### 9.5 缓存管理

设置 → 数据与备份 → 复盘数据：

- 显示缓存大小、会话数量、数据集数量。
- 「清理未被会话引用的数据」。
- 「清空全部回放缓存」（二次确认，提示会话需要重新准备数据）。
- 备份默认不包含回放缓存；可在导出时勾选「包含回放数据」。

## 11. 回放引擎规格

### 11.1 游标与推进

- 游标 `cursor_ts` = 已处理到的最后一根 M1 的**收盘时间**。
- 会话开始时，游标 = 第一根可交易 M1 的收盘时间；该根 M1 已完成，可以下单，市价单在下一根 M1 开盘成交。
- 每次推进处理一根 M1：
  1. 读取下一根 M1（`open_ts >= cursor_ts`）。
  2. 若有跳空/休市，直接跳到该根，不模拟空档时间。
  3. 用该根 OHLC 处理挂单触发、SL/TP、模板阶段。
  4. 用收盘价更新浮动盈亏、净值和资金曲线点。
  5. 更新 `cursor_ts = 该根收盘时间`。
  6. 通知图表更新当前显示周期 K 线。
- 到达 `end_ts` 后自动暂停，提示结束会话。

### 11.2 部分 K 线语义

- 显示周期 > 1m 时，当前显示 K 线由游标之前（含）的 M1 聚合而成。
- 例：15m 图，游标 10:05:00，当前 10:00 这根 15m K 线只包含 10:00–10:05 六根 M1，是高/低/收/量截至游标的「部分 K 线」。
- 游标进入下一根 15m 区间时，图表追加新 K 线；同一区间内只更新同一根 K 线（`time` 不变）。
- 这保证用户看到的是「当时能看到的信息」，而不是提前知道整根 15m 的收盘。

### 11.3 状态机

```
preparing → ready → running ⇄ paused → finished → archived
                ↘ error
```

| 状态 | 含义 | 可操作 |
|---|---|---|
| preparing | 数据准备中 | 取消、查看进度 |
| ready | 数据就绪，游标在起点 | 开始回放、修改参数 |
| running | 正在推进 | 暂停、下单、笔记 |
| paused | 暂停 | 播放、单步、下单、笔记、结束 |
| finished | 已结束，报告已生成 | 看报告、重新挑战、归档、删除 |
| archived | 已归档 | 取消归档、看报告、删除 |
| error | 数据/恢复失败 | 重试、删除 |

### 11.4 速度与调度

- 1x = 1 根 M1 / 1000ms。
- 0.5x = 1 根 / 2000ms；60x = 60 根 / 1000ms。
- 使用 `requestAnimationFrame` 或 100ms 定时器批量推进；图表推送最多 20 次/秒。
- 高速时如果模拟落后，允许一次推进多根，但**每一根都必须完整参与撮合和统计**，不能跳根。
- 窗口失去焦点/隐藏时自动暂停（`visibilitychange`），避免回来后墙钟补偿导致瞬间推进。
- 速度切换不改变游标，只改变下一次推进的节奏。

### 11.5 单步、跳转与进度条

- 单步：处理 1 根 M1。
- 下一根显示周期：循环处理 M1，直到显示周期的 `bucket` 变化。
- 向前跳转/拖动：循环处理所有中间 M1（撮合照常），完成后暂停；超过 1 天时显示确认「将快进 N 天并模拟所有订单」。
- 向后拖动：只移动图表可视范围，游标不动，顶部显示「正在回看 10-02 14:30，当前游标 10-08 14:30」，提供「回到当前」。
- MVP 不支持「退回到上一根继续交易」。R3 再做「回到此处重做」。

### 11.6 自动暂停

默认开启：

- 到达会话结束。
- 窗口隐藏。
- 发生保证金强平（若启用）。
- 用户点击「下单」展开下单票时（默认开，设置可关）。

默认关闭：

- 成交时暂停。
- 挂单触发时暂停。
- 触达模板阶段（保本/分批）时暂停。

### 11.7 确定性与恢复

- 引擎是纯函数：`step(state, bar, actions) -> newState + events`。
- 会话状态由「初始状态 + 按游标排序的动作日志」决定。
- 保存点：每 5 秒、暂停、下单、成交、平仓、笔记、结束。
- 崩溃恢复：
  1. 读取最近一次保存的游标和账户快照。
  2. 读取游标之后的动作（若有）。
  3. 从快照重放这些动作，得到与崩溃前一致的状态。
- 同一会话、同一动作序列，结果必须完全一致（用于测试和「重新挑战」对比）。

### 11.8 回看重做（R3）

- 用户在笔记或交易处点击「回到此处重做」。
- 系统把游标设到该时间点，删除其后的订单/成交/事件（保留笔记），按动作日志重算账户。
- 二次确认文案必须明确「将删除该时间之后的 N 笔模拟交易」。

## 12. 图表接入

### 12.1 独立 `ReplayDatafeed`

新增 `src/replay/datafeed.ts`，实现 `IDatafeedChartApi`，与现有 `GatewayDatafeed` 平行，不复用其实例：

| 方法 | 实现 |
|---|---|
| `onReady` | 同交易台，支持的分辨率一致 |
| `searchSymbols` | 只返回当前会话品种；不联网、不列其他品种 |
| `resolveSymbol` | 使用会话的 `symbol_snapshot`，不请求网关；`session: '24x7'`、`timezone: 'Etc/UTC'` |
| `getBars` | 从本地 buffer 聚合；只返回 `open_ts < cursor_ts` 的 K 线；不返回未来 |
| `subscribeBars` | 订阅回放引擎的 bar 更新；同一显示周期内更新同一根 K 线 |
| `unsubscribeBars` | 取消订阅 |
| `getServerTime` | 返回当前游标（服务器时间），不是真实当前时间 |
| 绘图模板 | 与交易台相同，但存储命名空间按会话隔离 |

### 12.2 M1 → 显示周期聚合

- 1m：直接使用 M1。
- 5m/15m/30m/1h/4h：按 `floor(open_ts / 周期秒)` 分桶。
- 1D：按服务器时间自然日分桶（00:00 边界）。
- 1W：按服务器时间周一 00:00 分桶。
- 1M：按服务器时间自然月分桶。
- OHLC：第一根 open、最高 high、最低 low、最后一根 close。
- volume：tick_volume 求和。
- 聚合结果缓存，按 `(resolution, bucket_ts)` 增量更新；切换周期时从 buffer 重建，不请求网关。

### 12.3 防止未来数据泄漏

硬性要求：

- `getBars` 和 `subscribeBars` 都必须过滤 `cursor_ts`。
- 图表切周期、向左翻页、指标重算都只能拿到游标之前的数据。
- 图表品种搜索只允许会话品种，禁止切到其他品种（否则会拉到实时行情）。
- 复盘页不挂载 `CalendarLayer`；财经日历可能包含未来事件。
- 复盘页不显示实时报价、实时告警、实时持仓。
- 不启用图表「比较品种」；若库默认开启，需禁用。
- 自动化测试：用一段包含明显未来行情的 fixture，断言 datafeed 在任何周期、任何调用下都不返回游标之后的 bar。

### 12.4 图表状态隔离

- 复盘图表使用独立容器和独立保存键（按 `session_id`）。
- 交易台的画线、指标组合、图表属性不能带入复盘；复盘的画线也不能带回交易台。
- 离开工作台时销毁复盘 widget，避免多实例占内存。
- 会话保存 `chart_state_json`，重新进入时恢复该会话的指标和画线。

### 12.5 订单/持仓可视化

- 当前持仓：入场价水平线 + SL/TP 水平线 + 右侧小块（手数、浮动盈亏、平仓按钮）。
- 挂单：触发价水平线 + 类型/方向标签。
- 成交标记：优先使用库支持的箭头/标记；若当前 Charting Library 版本不支持 `createExecutionShape`，回退为成交价水平短线 + 小标签（与现有 `priceLines.ts` 的绘制方式一致）。
- 拖动 SL/TP：复用交易台的「水平线 + React 覆盖层小块」模式，但写入复盘 store，不调用实盘 `position.modify`。
- 拖动改价后立即在本地更新，不等待网关；持久化异步进行。

## 13. 模拟撮合与账户

### 13.1 账户模型

- 每个会话独立：初始资金、余额、净值、已用保证金、可用保证金。
- 不读取实盘余额，不随实盘账户变化。
- 货币 = 会话创建时的账户货币；所有盈亏、佣金、点差成本都用该货币。
- 杠杆 = 会话创建时的选择；保证金 = 名义价值 / 杠杆（按品种 contractSize 计算）。
- 支持同一品种多个持仓（hedging 模式），不做净额合并。

### 13.2 价格与点差

- M1 K 线视为 **bid** 价格。
- `ask = bid + spread_points × point`。
- 买入开仓/买入平仓用 ask；卖出开仓/卖出平仓用 bid。
- 多头 SL/TP 用 bid 判断；空头 SL/TP 用 ask 判断。
- 点差在会话内固定；R3 可加「按小时/新闻放大」的可选模型。

### 13.3 订单类型与成交

| 订单 | 触发条件 | 成交价 |
|---|---|---|
| 市价买入 | 下单后的下一根 M1 | 下一根 open 的 ask |
| 市价卖出 | 下单后的下一根 M1 | 下一根 open 的 bid |
| Buy Limit | 后续 M1 的 `low + spread <= price` | `price` 的 ask；若开盘已低于 price，按 open 的 ask（更优） |
| Sell Limit | 后续 M1 的 `high >= price` | `price` 的 bid；若开盘已高于 price，按 open 的 bid（更优） |
| Buy Stop | 后续 M1 的 `high + spread >= price` | `price` 的 ask；若开盘已高于 price，按 open 的 ask（更差） |
| Sell Stop | 后续 M1 的 `low <= price` | `price` 的 bid；若开盘已低于 price，按 open 的 bid（更差） |

补充规则：

- 下单当根不成交；最早从下一根 M1 开始。
- 市价单始终按下一根开盘成交，避免「看到收盘价再按收盘价成交」的偷价。
- 挂单触发后一次性全额成交，不模拟部分成交。
- 挂单默认 GTC；会话结束仍未触发则自动取消。
- 价格按 `tickSize` 对齐；手数按 `volumeStep` 向下取整。
- 严格模式校验 `stopsLevelPoints`：SL/TP 距离不足时拒绝并提示。

### 13.4 SL/TP 与同根 K 线冲突

- 多头止损：`bid <= SL`；多头止盈：`bid >= TP`。
- 空头止损：`ask >= SL`；空头止盈：`ask <= TP`。
- 同一根 M1 内同时满足 SL 和 TP：**按 SL 先成交**（保守假设）。
- 跳空：
  - 多头止损：若该根 open 已低于 SL，按 open 的 bid 成交（更差）。
  - 多头止盈：若 open 已高于 TP，按 open 的 bid 成交（更优）。
  - 空头同理。
- 同一根 K 线内先触发挂单、后触发 SL：视为先成交再止损（最差情况）。
- 移动止损/保本：在每根 M1 处理完价格触发后、收盘前生效；只向有利方向移动。

### 13.5 盈亏、佣金与费用

- 浮动盈亏：
  ```
  priceDiff = side === 'buy' ? (bid - entry) : (entry - ask)
  profit = priceDiff / tickSize × tickValue × volume
  ```
  使用会话快照的 `tickSize` / `tickValue`，不依赖当前 MT5 账户。
- 佣金：每手单边佣金 × 手数，开仓和平仓各收一次。
- 点差成本已包含在 ask/bid 差中，不重复计算。
- 隔夜利息：MVP 不模拟，报告标注「未计隔夜利息」。R2 可加简化的每日掉期。
- 统计显示带「≈」的金额为估算；报告底部注明「基于 M1 OHLC 的保守撮合，与真实 tick 成交可能存在差异」。

### 13.6 保证金与强平

- 已用保证金 = `contractSize × volume × price / leverage`（按品种货币近似）。
- 保证金水平 = 净值 / 已用保证金 × 100%。
- MVP：只显示，不强平；净值 <= 0 时暂停并提示「模拟账户已爆仓」。
- R2：可配置强平线（默认 50%），触发时按当前价平掉全部持仓并暂停。

### 13.7 手数与风险计算

- 风险金额 = 净值 × 单笔风险 %（复用交易模板的设置）。
- 每手在 SL 处的损失 = `|entry - sl| / tickSize × tickValue`。
- 手数 = `floor(风险金额 / 每手损失 / volumeStep) × volumeStep`，夹在 `[minVolume, maxVolume]`。
- 无 SL 时：
  - 标准模式：使用用户输入手数，提示「未设置止损，无法按风险计算手数」。
  - 严格模式：禁止下单。
- 风险预览显示：风险金额、占净值 %、R:R、预计保证金、点差成本、佣金。
- MVP 用前端公式估算；R2 可在连接 MT5 时调用网关的 `order_calc_profit` / `order_calc_margin` 做精确校验（仍然不发送订单）。

### 13.8 模板行为

复用交易台下单模板（`TradeTemplate`）：

- 下单时按模板计算手数、TP（按 R 倍数）、初始 SL。
- R2 起，回放引擎自动执行模板阶段：
  - 浮盈达到 `atR`：平掉 `closePercent`，或把 SL 移到开仓价。
  - 每个阶段只触发一次。
  - 触发时记录事件，报告中显示「模板执行情况」。
- 自动保本/移动止损后置到 R2 末或 R3。

**交易明细**

| 列 | 说明 |
|---|---|
| # | 序号 |
| 方向 | 多/空 |
| 手数 | |

| 持仓时长 | |
| SL / TP | 初始值 |
| 风险 | 金额与 % |
| 盈亏 | 含佣金 |

### 16.3 指标口径

| 指标 | 公式 |
|---|---|
| 净盈亏 | Σ（已平仓盈亏 + 佣金） |
| 收益率 | 净盈亏 / 初始资金 |
| 胜率 | 盈利交易数 / 已平仓交易数 |
| 盈亏比（Profit Factor） | 总盈利 / 绝对总亏损 |
| 期望 | 净盈亏 / 已平仓交易数 |
| 平均盈利 / 平均亏损 | 各自算术平均 |
| 初始风险 | 开仓时 `abs(entry - SL) / tickSize × tickValue × volume`；无 SL 记为空 |
| R 倍数 | 交易盈亏 / 初始风险；无风险的不参与 R 统计 |
| 总 R / 平均 R | 有 R 值交易的求和 / 平均 |
| 最大回撤 | 逐 M1 净值曲线的峰值到谷值最大跌幅（金额与 %） |
| MFE / MAE | 持仓期间按每根 M1 的有利/不利极值折算成账户货币 |
| 持仓时长 | `exit_ts - entry_ts` |
| 暴露时间 | 有持仓的 M1 数 / 总 M1 数 |
| 平均 R 的覆盖率 | 有 R 值的交易数 / 总交易数 |

说明：

- 净值曲线按每根 M1 收盘计算，包含浮动盈亏；报告图表最多下采样到 500 个点。
- 与实盘 journal 的统计差异：
  - 实盘盈亏来自券商成交，含真实滑点、隔夜利息、手续费。
  - 回放基于 M1 OHLC 保守撮合，不含隔夜利息。
  - 对比时必须显示口径提示，不能直接说「你实盘比复盘差多少」。

### 16.4 导出

- 交易明细 CSV（UTF-8 BOM，与现有导出风格一致）。
- 会话 JSON（参数、成交、笔记、统计），用于备份/迁移。
- 报告截图/PDF 后置到 R3/R4。
- 导出不包含实盘账户凭据。

## 17. 会话状态、恢复与安全隔离

### 17.1 自动保存

| 时机 | 保存内容 |
|---|---|
| 每 5 秒（播放中） | 游标、余额、净值、持仓/挂单快照 |
| 暂停 / 单步 / 跳转 | 同上 |
| 下单 / 改单 / 撤单 | 订单与事件 |
| 成交 / 平仓 | 持仓、余额、事件 |
| 笔记新增/修改 | 笔记 |
| 结束 | 最终状态、统计、报告 |

### 17.2 崩溃恢复

- 启动时扫描 `replay_sessions` 中 `running` 状态但进程已退出的会话，改为 `paused`。
- 打开会话时，若保存点与动作日志不一致，按动作日志重放。
- 恢复失败时允许「从最近保存点继续」或「从头开始」。

### 17.3 与实盘隔离

- 独立 store：`useReplay`，不复用 `useApp` 中的持仓、草稿、预览。
- 独立网关命名空间：`replay.*`；实现上不得调用 `order.place`、`position.close`、`order_send`。
- 独立数据库：`data/replay.db`。
- 独立截图目录：`data/replay-shots/`。
- 独立图表 datafeed：`ReplayDatafeed`。
- UI 常驻「模拟」徽标；复盘页不显示实盘账户余额卡（左侧导航外部的实盘信息仍可见，但工作台内只显示模拟账户）。
- 复盘成交不进入 `journal`、`executions`、`audit`。
- 复盘期间实盘告警/成交提示默认静音（R2 可配置），避免打断。
- 自动化测试：静态检查 `replay` 模块不得 import 下单函数；集成测试断言复盘操作不会产生 `executions` 记录。

### 17.4 离线

- 数据已缓存 + 会话已创建时，断网/MT5 断开仍可回放。
- 图表库来自本地 `public/charting_library/`。
- 品种规格来自会话快照，不实时请求。
- 需要新数据或新会话时，必须连接 MT5。

## 18. 数据模型

### 18.1 存储位置

新增独立 SQLite：`<数据目录>/data/replay.db`（`%LOCALAPPDATA%\MyTrade\gateway\data\replay.db`）。

理由：

- 回放 K 线数据量大，独立库便于清理和备份。
- 不污染实盘 `mytrade.db` 的 journal/executions/audit。
- WAL 模式，与主库相同。

### 18.2 表结构

```sql
-- 数据集：按品种共享，可被多个会话复用
CREATE TABLE IF NOT EXISTS replay_datasets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  symbol TEXT NOT NULL,
  timeframe TEXT NOT NULL DEFAULT '1',
  start_ts INTEGER NOT NULL,
  end_ts INTEGER NOT NULL,
  first_ts INTEGER,
  last_ts INTEGER,
  bar_count INTEGER NOT NULL DEFAULT 0,
  missing_days INTEGER NOT NULL DEFAULT 0,
  source TEXT NOT NULL DEFAULT 'mt5',
  status TEXT NOT NULL DEFAULT 'ready', -- preparing / ready / partial / error
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  UNIQUE(symbol, timeframe, start_ts, end_ts)
);

-- M1 K 线：按品种和时间共享
CREATE TABLE IF NOT EXISTS replay_bars (
  symbol TEXT NOT NULL,
  ts INTEGER NOT NULL,          -- M1 开盘时间（服务器时间当 UTC）
  open REAL NOT NULL,
  high REAL NOT NULL,
  low REAL NOT NULL,
  close REAL NOT NULL,
  volume REAL NOT NULL DEFAULT 0,
  PRIMARY KEY (symbol, ts)
) WITHOUT ROWID;

-- 会话
CREATE TABLE IF NOT EXISTS replay_sessions (
  id TEXT PRIMARY KEY,          -- UUID
  name TEXT NOT NULL,
  symbol TEXT NOT NULL,
  display_resolution TEXT NOT NULL DEFAULT '15',
  start_ts INTEGER NOT NULL,
  end_ts INTEGER NOT NULL,
  warmup_bars INTEGER NOT NULL DEFAULT 1000,
  initial_balance REAL NOT NULL,
  balance REAL NOT NULL,
  equity REAL NOT NULL,
  currency TEXT NOT NULL,
  leverage INTEGER NOT NULL,
  spread_points REAL NOT NULL,
  commission_per_lot REAL NOT NULL DEFAULT 0,
  slippage_points REAL NOT NULL DEFAULT 0,
  symbol_snapshot TEXT NOT NULL, -- JSON：品种规格快照
  rules_json TEXT,               -- JSON：训练规则
  status TEXT NOT NULL,          -- preparing/ready/running/paused/finished/archived/error
  cursor_ts INTEGER,
  cursor_index INTEGER NOT NULL DEFAULT 0,
  chart_state_json TEXT,
  stats_json TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  finished_at INTEGER
);

-- 模拟订单（含已成交/已取消）
CREATE TABLE IF NOT EXISTS replay_orders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  symbol TEXT NOT NULL,
  side TEXT NOT NULL,            -- buy / sell
  kind TEXT NOT NULL,            -- market / limit / stop
  volume REAL NOT NULL,
  price REAL,                    -- 挂单触发价；市价为空
  sl REAL,
  tp REAL,
  status TEXT NOT NULL,          -- pending / filled / cancelled / rejected
  reject_reason TEXT,
  position_id INTEGER,
  created_ts INTEGER NOT NULL,
  activated_ts INTEGER,          -- 最早可触发的 M1 收盘时间
  filled_ts INTEGER,
  fill_price REAL,
  comment TEXT,
  tag TEXT
);

-- 模拟持仓（未平仓 exit_ts 为空）
CREATE TABLE IF NOT EXISTS replay_positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  order_id INTEGER,
  symbol TEXT NOT NULL,
  side TEXT NOT NULL,
  volume REAL NOT NULL,
  initial_volume REAL NOT NULL,
  entry_price REAL NOT NULL,
  entry_ts INTEGER NOT NULL,
  sl REAL,
  tp REAL,
  exit_price REAL,
  exit_ts INTEGER,
  profit REAL,
  commission REAL NOT NULL DEFAULT 0,
  close_reason TEXT,             -- manual / tp / sl / stop_out / session_end
  risk_amount REAL,
  mfe REAL,
  mae REAL,
  tag TEXT,
  note_id INTEGER
);

-- 笔记
CREATE TABLE IF NOT EXISTS replay_notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  cursor_ts INTEGER NOT NULL,
  price REAL,
  kind TEXT,                     -- entry / exit / mistake / emotion / other
  text TEXT NOT NULL,
  tags TEXT,
  screenshot TEXT,
  position_id INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 事件/动作日志：用于恢复、时间线、审计
CREATE TABLE IF NOT EXISTS replay_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  ts INTEGER NOT NULL,
  kind TEXT NOT NULL,            -- play/pause/order/fill/close/sl_move/note/rule_violation/finish
  payload_json TEXT
);

CREATE INDEX IF NOT EXISTS idx_replay_sessions_status
  ON replay_sessions(status, updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_replay_orders_session
  ON replay_orders(session_id, status, created_ts);
CREATE INDEX IF NOT EXISTS idx_replay_positions_session
  ON replay_positions(session_id, exit_ts);
CREATE INDEX IF NOT EXISTS idx_replay_notes_session
  ON replay_notes(session_id, cursor_ts);
CREATE INDEX IF NOT EXISTS idx_replay_events_session
  ON replay_events(session_id, ts);
```

### 18.3 保留与清理

- 删除会话：删除该会话的订单、持仓、笔记、事件；数据集保留（可能被其他会话引用）。
- 归档：只改状态，不删数据。
- 清空缓存：删除 `replay_bars` 和 `replay_datasets`；会话保留，但下次打开需要重新准备。
- 数据目录纳入备份时，默认排除 `replay.db`；用户可勾选包含。

- `replay.orders.record` / `positions.record` 是**持久化**接口，不是下单接口；网关只写库，不调用 MT5。
- 撮合在前端完成；网关不参与逐根推进。
- 所有 `replay.*` 方法在实现上不得 import/调用 `order.place`、`position.close`、`mt5.order_send`。
- 统计在网关计算，方便复用 `journal.py` 的指标函数和导出。

### 19.2 事件

| 事件 | 数据 |
|---|---|
| `replayJob` | `{jobId, symbol, from, to, doneBars, totalBars, chunk, status, error?}` |

回放推进、成交、持仓变化不通过网关事件广播；它们是前端本地事件，只批量持久化。

### 19.3 数据准备调度

- 网关工作线程的命令队列支持优先级：交易/行情 > 回放数据准备。
- 每个准备块执行前检查是否有高优先级命令；有则让出。
- 准备任务状态落库，应用重启后可继续/标记失败。

### 20.3 引擎设计

- `engine/` 全部为纯函数，不依赖 React、DOM、网关。
- 输入：`EngineState`、下一根 M1、待处理动作；输出：新状态 + 事件列表。
- `EngineState` 包含：游标、余额、净值、订单、持仓、统计累加器。
- 单元测试建议引入 Vitest（当前项目没有 JS 测试框架，新增一个轻量 devDependency），覆盖：
  - 市价单下一根开盘成交。
  - 限价/停损触发与跳空。
  - 同根 SL/TP 冲突。
  - 点差对多空触发方向的影响。
  - M1 → 5m/15m/1h/1D 聚合。
  - 手数/风险/保证金计算。
  - 净值曲线与最大回撤。
- 网关侧 pytest 覆盖：数据准备分块、去重、覆盖统计、会话 CRUD、统计口径、`replay` 不调用下单。

### 20.4 性能设计

- K 线缓冲按 30 天窗口加载；游标距缓冲尾部小于 7 天时预取下一段。
- 显示周期聚合缓存按 `(resolution, bucket_ts)` 增量维护；切换周期时重建一次。
- 图表推送节流到 20fps；内部模拟不节流。
- 笔记列表和交易列表虚拟滚动（超过 200 条时）。
- 报告图表最多 500 个采样点。

## 21. 边界与异常

| 场景 | 处理 |
|---|---|
| 区间内无数据 | 禁用创建，提示换品种/区间 |
| 起点无数据 | 提示并顺延到下一根可用 M1 |
| 工作日缺口 > 5% | 标记「部分可用」，允许创建并提示 |
| MT5 未连接且数据未缓存 | 禁用创建，提示先连接终端 |
| MT5 未连接但数据已缓存 | 允许回放，顶部显示「离线数据」 |
| 数据准备中关闭应用 | 任务标记中断；下次打开可继续/重试 |
| 回放中行情数据缺失 | 暂停，提示缺失区间，允许跳过（跳过后统计标注覆盖不足） |
| 会话引用的数据被清理 | 打开时提示重新准备缺失区间 |
| 应用崩溃 | 恢复最近保存点；最多丢 5 秒游标 |
| 游标到达结束 | 自动暂停，提示结束会话 |
| 结束时仍有持仓 | 提示按当前价平仓并结束 |
| 模拟账户净值 <= 0 | 暂停，提示爆仓；禁止继续开仓 |
| 品种规格变化 | 使用会话快照，不受当前券商影响 |
| 用户切换实盘账户 | 复盘不受影响；会话货币/杠杆不变 |
| 浏览器窗口隐藏 | 自动暂停 |
| 图表库不可用 | 显示错误页，提供返回列表 |
| 导出失败 | 提示路径/权限，不丢会话数据 |

## 22. 非功能需求

### 22.1 性能

- 列表页 100 个会话加载 < 300ms。
- 打开已缓存会话 < 1s（不含图表初始化）。
- 1 个月 M1 准备 < 30s（终端已有数据）；1 年 < 3 分钟。
- 10x 回放时 CPU 占用目标 < 20%（普通桌面 CPU）。
- 内存：1 年数据的会话，前端缓冲目标 < 150MB；超出时淘汰远离游标的旧数据。

### 22.2 可靠性

- 任何持久化失败都要提示，不能静默丢成交。
- 网关数据准备失败可重试，不影响已有会话。
- 回放引擎不依赖网络；网络中断不暂停回放（除非需要新数据）。
- 所有时间戳使用整数秒，避免浮点误差。

### 22.3 一致性

- 统计口径与实盘日志共用函数；差异只在数据来源和费用模型。
- 同一会话多次打开，报告数字一致。
- 重新挑战复制参数，不复制成交和笔记。

### 22.4 可用性

- 所有按钮有禁用态和原因提示。
- 危险操作（删除、清空、重新开始、跳转超过 1 天）二次确认。
- 空状态有明确下一步。
- 键盘可完成播放/暂停/单步/下单/笔记。
- 颜色语义与交易台一致：盈利绿、亏损红、强调色只用于主操作。

### 22.5 安全与隐私

- 所有数据本机存储，不上传。
- 不保存 MT5 密码；会话快照不含账户凭据。
- 导出文件不含账户号/服务器等敏感信息（可脱敏）。
- 复盘模块与实盘下单代码物理隔离。

## 24. 分期计划与工作量

| 阶段 | 内容 | 交付物 | 预计 |
|---|---|---|---|
